# Fastab

一键呼出的markdown记事本（Windows x64系统）。

当前版本：**2.1.1**

## 核心能力与操作说明

* 开机自启，后台运行，一键呼出（默认Alt + Z），随时写入，markdown渲染，一键收回（默认Alt + Z）。
* **笔记分类**：顶栏那一排就是分类条目（`默认` 分类固定存在），点击即可切换。分类之间互相独立，切到哪个分类就只看/只操作该分类下的笔记。
* 每个分类都带**与文字同色的外框**；当前分类用**反色填充**（填充色 = 该分类的颜色，文字取底色）做区分，深色主题下自动适配。
* **拖动排序（两种方式都行）**：
  * 顶栏分类条目**直接按住左右拖动**即可调整顺序，松手立即保存（「默认」固定第一位，拖不动；回收站不参与排序）；
  * 也可以点「编辑」进弹窗里拖动，改完点「确定」统一生效。
* 新建分类：「**新建分类**」按钮紧靠搜索框左侧，点击输入名称即可（禁止空名、禁止重名，最长 24 字）。
* 编辑分类：「新建分类」右侧的「**编辑**」按钮打开分类编辑框，每一行 = 拖动手柄 + 名称输入框 + 删除按钮；**整行（输入框除外）都能按住拖动**：
  * 「默认」分类**固定第一位**，不可拖动、不可改名、不可删除；
  * 删除的分类里的笔记会**移入回收站**（可在回收站里恢复或彻底删除）；
  * 正在查看的分类被改名时视图自动跟随新名字，被删除时自动回到「默认」。
* 创建：点击顶栏「新建」按钮，在**当前分类**下创建空白笔记（在「回收站」视图点新建时，会先切回默认分类再创建）。
* 打开：点击顶栏「新建」右侧的「打开」按钮，选择一个 `.md` 文件，会**在当前分类新建一条笔记**——文件名（去掉 `.md`）作为标题，文件内容作为正文，新笔记排在分类首位但不自动打开。文件对话框默认停在上一次用过的文件夹。
* 排序：笔记卡片可「置顶 / 前移 / 后移/ 置底」。
* 移动：笔记卡片右下角「**移动**」按钮会弹出分类列表，选中后点「确定」，笔记即移动到该分类并**排在该分类第一位**（其它笔记顺序不变）。
* 三种界面：**工作台**界面、**查看**界面（渲染markdown）、**编辑**界面。
    **工作台**单击笔记卡片进入**查看**，工作台双击笔记卡片进入**编辑**。
    **查看**时双击或按 Enter 进入**编辑**，按 Esc 返回**工作台**。
    **编辑**时按“保存”按钮或 Ctrl + Enter回到**查看**；按“关闭”按钮实际是“保存并关闭”，回到**工作台**。
* 查看界面下，顶栏显示笔记小块（**只显示当前分类下的笔记**），可直接点击小块或 Ctrl + PageUp / PageDown 左右切换。**编辑界面下小块置灰不可切换。**
* 显示：可设置大字体，对近视用户友好。
* 数据在「文档\\Fastab\\data」，每次保存自动备份到「文档\\Fastab\\FastabBackup」（最多 20 份）；设置页可查看备份目录与立即备份。
* 设置页支持「导出笔记及配置 / 导入笔记及配置」（**导入直接重置所有数据**，导入时选择文件夹内部需包含notes.json与preferences.json两个文件）。
* 查看界面顶部（时间右侧）有「导出」按钮（外观与「编辑」按钮一致），可把当前笔记正文导出为 `.md` 文件（文件名取笔记标题）；对话框默认停在**上一次用过的文件夹**，导出结果（完整路径）会显示在按钮右侧约 4 秒。
* 工作台切到「回收站」视图时，标签右侧出现「清空回收站」按钮，一键清空（无二次确认）。回收站里的卡片只有「恢复 / 永久删除」，没有「移动」。
* 编辑界面**允许正文为空**：清空内容后点「保存 / 关闭」会保留一条空笔记。
* 卡片预览与查看界面的**字体完全一致**（含反引号内的行内代码：都用同一套等宽字体栈，中文回退到雅黑而不是宋体）。

## 快捷键

|快捷键|功能|可否修改|
|:-:|:-:|:-:|
|`Alt + Z`|呼出/收起面板（默认值）|可改（设置页）|
|`Enter`|笔记打开时进入编辑；卡片聚焦时进入编辑|固定|
|`Esc`|查看笔记时返回工作台（编辑模式下不响应）|固定|
|`Ctrl + PageUp/PageDown`|查看时切换到上一条 / 下一条笔记（编辑模式下不响应）|固定|
|`Ctrl + Enter`|编辑时保存|固定|
|`Ctrl + Z`|撤销|固定|
|`Ctrl + Shift + Z`|重做|固定|
|`Tab` / `Shift + Tab`|编辑时缩进 / 反缩进选中行|固定|
|`Ctrl + D`|编辑时删除光标所在行 / 选区覆盖的行|固定|
|`Ctrl + F`|编辑时打开查找面板|固定|
|`Ctrl + H`|编辑时打开查找替换面板|固定|



## 历史版本

### 2.1.1 更新内容

#### 修复：分类拖不动（2.1.0 的拖拽实现不可靠）

2.1.0 用的是浏览器原生 HTML5 拖拽（`draggable` + `dragstart/dragover/drop`），实测有三个致命限制：

* `draggable` 挂在整行上，但整行 90% 宽度是名称输入框，**从输入框上按下不会启动原生拖拽**（浏览器会去做文本选择），只有按左侧 22px 手柄才可能拖；
* 手柄里是 SVG，**从 SVG 子元素起拖在 WebView2 里本身不稳定**；
* 拖到行间缝隙 / 列表底部松手时没有 drop 目标，等于没放。

**现在改为 pointer 事件自绘拖拽**（`pointerdown` / `pointermove` / `pointerup` + 按行中线实时换位），不再依赖浏览器原生 DnD：

* 编辑弹窗里**整行（输入框、删除按钮除外）按住即可拖动**，有 4px 阈值区分点击与拖动，拖动中有高亮与半透明反馈；
* 「默认」分类仍然锁定在第一位（拖到它前面会被夹回第 2 位）。

#### 新增：顶栏分类条目直接拖动排序

* 顶栏的分类 chip **按住左右拖**即可调整顺序，松手立即落盘（走同一个 `apply_category_edits` 命令，不弹窗）；
* 5px 阈值区分"点击切换视图"与"拖动排序"，拖动结束那一次 click 会被忽略，不会误切视图；
* 「默认」chip 不可拖、回收站 chip 不参与排序；
* 落盘失败时自动回读后端顺序，界面不会停在错误的顺序上。

#### 版本与产物

* 版本号升至 **2.1.1**（`package.json`、`package-lock.json`、`tauri.conf.json`、`Cargo.toml`、`Cargo.lock`、设置页版本号同步）。
* 安装包改名 **`Fastab\_2.1.1\_x64-setup.exe`**。

### 2.1.0 更新内容

#### 新增「编辑」：分类的排序 / 改名 / 删除

* 「新建分类」右侧新增「**编辑**」按钮，打开分类编辑框，每一行由三部分组成：
  * **拖动排序**：左侧灰色列表手柄，按住拖动即可调整分类顺序（「默认」固定第一位，不参与拖动）；
  * **改名**：中间输入框，直接改文字即可（「默认」只读）；
  * **删除**：右侧灰色垃圾桶图标，点击从列表中移除（「默认」显示为锁图标，不可删除）。
* 所有改动都先记在弹窗里的**本地副本**上，点「确定」才一次性提交；点「取消」或点遮罩关闭则完全丢弃。
* 提交时后端在**一次事务**里完成：更新分类顺序与名称 → 按 old→new 映射重写每条笔记的 `category` → 被删除分类里的笔记**移入回收站**（分类归到「默认」）→ 一次落盘，不会出现"改了一半"的中间态。
* 校验：空名、重名、超过 24 字、保留字 `trash` 都会被拦下；「默认」不能改名/删除；分类不能全部删空。
* 视图联动：正在查看的分类被改名 → 视图自动跟到新名字；被删除 → 自动回到「默认」。

#### 按钮位置调整

* 「新建分类」「编辑」移动到**紧靠搜索框左侧**（原本"新建分类"留在分类条那一侧，和搜索框之间隔着一大段空白）。

#### 分类条配色

* 每个分类条目都显示**外框，边框色与该分类文字色一致**；
* 当前分类改为**反色填充**：填充色 = 该分类的颜色，文字取卡片底色（深色主题下自动适配，不会出现白字压浅色底）；
* 计数徽标改为跟随文字色（`currentColor`），选中态下自动变成反色；
* 回收站条目沿用弱化色，但同样有外框，选中态同样是反色填充。

#### 版本与产物

* 版本号升至 **2.1.0**（`package.json`、`package-lock.json`、`tauri.conf.json`、`Cargo.toml`、`Cargo.lock`、设置页版本号同步）。
* 安装包改名 **`Fastab\_2.1.0\_x64-setup.exe`**。

### 2.0.0 更新内容

> ⚠️ **破坏性变更**：`notes.json` 从"纯数组"改为对象形态 `{ "version": 2, "categories": [...], "notes": [...] }`，
> **不再兼容 1.x 的数据文件**。升级后第一次保存前，旧的 `notes.json` 会被自动改名留档为
> `notes-1.x-<时间戳>.json.bak`（同目录），避免被直接覆盖；但 1.x 的笔记不会自动导入 2.0.0。

#### 新增笔记分类

* 顶栏原来的「全部 / 已归档 / 回收站」改为**分类条目 + 回收站**：
  * 「全部」不再是"显示所有笔记"，而是变成一个**默认分类**，名称改为「**默认**」；
  * 「已归档」视图**删除**；
  * 回收站仍是独立视图，位置在分类条最右。
* 分类条右侧、搜索框左侧新增「**新建分类**」按钮，弹框输入名称即可创建（空名/重名/超 24 字会被拒绝）。新建后自动切到该分类。
* 分类列表与笔记一起存在 `notes.json` 里；「默认」分类永远存在且排第一，空分类也会保留。

#### 新增「移动」：把笔记挪到别的分类

* 卡片右下角原来的「归档」按钮位置改为「**移动**」按钮，点击弹出**当前分类列表**，选中后点「确定」：
  * 笔记被移动到目标分类，并**排在该分类第一位**（实现方式：把它的排序值设成该分类最小值 − 1，其它笔记顺序不受影响）；
  * 取消不做任何改动；回收站里的卡片**没有**移动按钮（保持「恢复 / 永久删除」）。

#### 「新建」「打开」落在当前分类

* 「新建」：在**当前所在分类**下新建笔记；在回收站视图点「新建」会先切回默认分类。
* 「打开 .md」：导入的笔记同样落在当前分类。
* 查看界面顶栏的笔记小块**只显示当前分类下的笔记**。

#### 彻底删除归档功能

* 删除 `toggle_archive` 命令、`is_archived` 字段与相关排序/筛选逻辑、卡片归档按钮与图标、以及 `archive / unarchive / archived` 三处文案。
* `reorder_notes` 的 `is_archived_view` 参数改为 `category` + `is_trash_view`，保证「置顶 / 前移 / 后移 / 置底」在分类视图下依然正确。

#### 卡片字体与查看界面统一

* 之前卡片预览里的**行内代码**（反引号内容）没有字体规则，会落到浏览器默认 `monospace`，中文在 Windows 上回退成**宋体**；查看界面则用了 `--ws-font-mono`（中文回退雅黑），两边观感不一致。
* 现在卡片补上 `pre / code / kbd / samp` 规则，与查看界面使用**同一套等宽字体栈**，两边完全一致。

#### 版本与产物

* 版本号升至 **2.0.0**（`package.json`、`package-lock.json`、`tauri.conf.json`、`Cargo.toml`、`Cargo.lock`、设置页版本号同步）。
* 安装包改名 **`Fastab\_2.0.0\_x64-setup.exe`**。

### 1.7.0 更新内容

#### 新增「打开」：把本地 `.md` 文件变成一条笔记

* 工作台顶栏「新建」右侧新增「打开」按钮（与「新建」同为主色底 + 文字，无图标）。
* 点击弹出系统文件对话框，只接受 `.md` 后缀（`.MD` 也认）；选中后**新建一条笔记**：
  * **标题** = 文件名（去掉 `.md`）；
  * **正文** = 文件内容（markdown 源码，原样写入，不做命令展开）。
* 新笔记插入「全部」视图首位；若当时在「回收站 / 已归档」视图或带着搜索词，会自动切回「全部」并清空搜索，保证立刻可见。**不会自动进入该笔记**。
* 编码：UTF-8（含 BOM）优先；不是合法 UTF-8 时按 GBK(936) 再解一次（Windows 系统 API，未引入新依赖）；仍失败才按 lossy 兜底，避免中文 `.md` 出现乱码。
* 同一文件重复打开会产生多条笔记（按设计如此，不做去重）。

#### 文件对话框记住「上一次的文件夹」

* 新增偏好字段 `lastFileDialogDir`（写入 `preferences.json`，旧配置缺少该字段时按空串处理，向后兼容）。
* 「打开」与「导出」**共用**这个记忆：每次选完文件/保存完文件，都会把该文件所在目录记下来；下次两个对话框都从这里开始。
* 首次使用（还没有记录）仍回退到 `D:\Downloads` → 系统「下载」目录，行为与 1.6.x 一致。

#### 「导出」按钮外观与路径显示

* 导出按钮改为与「编辑」按钮同一套样式（`btn primary`，主色底），不再与「关闭」同款。
* 导出结果提示（含完整保存路径）宽度由 240px 提高到 **720px（3 倍）**，并让头部在空间不足时换行而不是把路径截断，路径基本可以完整读完（极端超长路径仍保留悬停查看全文）。

#### 版本与产物

* 版本号升至 **1.7.0**（`package.json`、`package-lock.json`、`tauri.conf.json`、`Cargo.toml`、`Cargo.lock`、设置页版本号同步）。
* 安装包改名 **`Fastab\_1.7.0\_x64-setup.exe`**。

### 1.6.0 更新内容

#### 编辑模式：正文为空也可以保存 / 关闭

* 之前：清空正文后点「保存」会**静默跳过写盘**，界面回到查看态但正文还是旧的，看起来像"空内容保存不了"。
* 现在：正文为空也会照常写回，保存后**保留一条空笔记**；「关闭」依旧是"保存并关闭"。

#### 工作台回收站：新增「清空回收站」

* 只有切到「回收站」视图时，才会在「回收站」标签**右侧**出现「清空回收站」按钮（带垃圾桶图标）；其它视图不显示。
* 点击立即清空回收站，**不弹二次确认**；清空后列表与三个标签的数量同步刷新；回收站为空时按钮置灰。
* 后端 `empty_trash` 命令在 1.5.x 已实现但**未注册到命令表**，本次补齐并接入界面。

#### 查看模式：新增「导出」

* 查看笔记时，顶部时间**右侧**新增「导出」按钮（与「关闭」按钮同一套样式，与时间之间留出间距）。
* 点击弹出系统保存对话框：默认目录 **`D:\Downloads`**（该目录不存在时回退到系统「下载」目录），默认文件名取笔记标题 **`标题.md`**；标题为空用 `未命名.md`，标题中的非法字符会被替换、过长会被截断。
* 导出内容是笔记**正文（markdown 源码）**，**不含标题**；导出成功/失败后按钮旁会短暂显示结果与保存路径。

#### 版本与产物

* 版本号升至 **1.6.0**（`package.json`、`package-lock.json`、`tauri.conf.json`、`Cargo.toml`、`Cargo.lock`、设置页版本号同步）。

### 开发

* Node.js（本项目使用 npm，锁文件为 `package-lock.json`）
* Rust stable（Windows 使用 MSVC 工具链）
* Tauri 2 所需系统依赖（Windows 需要 WebView2 Runtime）

> 源码目录默认\*\*不包含\*\* `node\\\_modules` 与 `src-tauri/target`（构建中间产物）。首次构建先执行 `npm install`（或 `pnpm install`）。

```bash
npm install
npm run tauri dev
npm run check
cargo check --manifest-path src-tauri/Cargo.toml
```

打包 NSIS 安装版：

```bash
npm run tauri build -- --bundles nsis
```

产物：

```text
src-tauri/target/release/bundle/nsis/Fastab\\\_1.5.6\\\_x64-setup.exe
```

> 仓库里已附带的安装包位于 `release\\\\Fastab\\\_1.5.6\\\_x64-setup.exe`；源码目录不含 `node\\\_modules`、`src-tauri/target`、`.svelte-kit`、`build` 等构建中间产物。
